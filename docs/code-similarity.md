# 代码检测：相似度比对与 AI 生成识别

[文档首页](README.md) · [项目首页](../README.md)

## 使用方式

教师打开“作业”，在自己发布的作业操作区点击“代码检测”，选择“相似度比对”或“AI 生成识别”。

## AI 生成识别

### 检测方式

统一 Docker 部署默认使用 `auto`：
Python、Java、C++、Go 使用本地 DroidDetect 二分类，默认 Base-Binary，
可通过 `ai_detection.model: large` 切换 Large-Binary。其他语言使用上下文分析。
修改配置后执行 `python3 deploy.py up -d --build`，按配置替换检测容器。
本地分类无需 DeepSeek 密钥和同题样本；页面根据服务端能力隐藏样本准备步骤，
报告展示完整代码分块、词元覆盖及片段分数，不生成虚构的五维度解释。
本地分类故障不会自动转发给外部模型。切换配置不重算旧报告，须显式重新生成。

`GET /api/v1/assignments/:id/ai-detection/options` 返回当前语言的检测方式、
是否启用及是否需要样本，仅作业所属教师可读，不返回内部服务地址或密钥。
本地分类报告使用 `scoringVersion=droiddetect-binary-chunks-v1`，独立保存 `localDetection`，
包含片段行范围、词元数、原始分类分数、完整覆盖状态、预处理版本和模型版本。
Go 后端核对词元覆盖、片段权重及综合分的一致性，失败不保存新报告。
页面及 HTML/PDF 导出保留片段数据；检测结果不改变成绩。

本地分类分数不是逐行生成比例或校准概率；保留原始注释与空白，分块加权尚待课程数据验证。
检测底层通过 `AIDetectionProvider` 接口封装。API 根据 provider 声明读取材料，
前端通过 options 接口决定样本准备步骤。将 `ai_detection.provider` 改为 `ds` 或
`deepseek` 即可全部使用下文的五维度分析；评分、数据保存和导出接口继续复用。
部署及其完整适用范围见 [Docker 部署与迁移](docker-deployment.md)。

### 上下文分析流程

`starterCode` 是教师提供给学生的公开参考框架，不是标准答案。检测提示明确排除公共框架作为来源依据；选填的参考答案不传给识别模型，也不参与比对。相似度比对自动排除框架，教师可继续补充其他公共代码。

- **全班识别**：每名学生取最新一次提交，逐份调用现有 DeepSeek 服务；时间相同时取编号最大的提交。
- **单份识别**：可选择当前或历史提交。识别独立于作业的 AI 评分开关；优先复用本份提交已保存的沙箱结果，缺失时通过已启用的沙箱执行作业已配置用例，不改变成绩。无用例、沙箱未启用或运行服务失败时据实记录缺失原因，并继续来源分析；取消请求则停止。
- 展示 AI 率估计、维度覆盖率、多维度原始分与有效分、判断理由、代码引用和汇总规则。旧报告保留原有数据及自评置信度并明确标记旧版，重新生成后采用新规则。模型名称与调用次数不在页面展示。证据不足时展示“证据不足”，不生成百分比。
- 详情优先展示明确的生成倾向、AI 率估计与代码依据；核验材料、测试结果和补充说明默认折叠。整体倾向由后端计算并生成，模型仅返回各维度的事实分析，不因缺少历史版本或参考实现自动拒绝估计。补充说明可为空，最多两条，只保留影响结论且核验记录尚未说明的问题，不逐份重复通用局限；确实无有效来源证据时仍保留“证据不足”。导出保留完整核验内容，空补充说明不显示标题。
- 详情与导出报告增加“核验材料”和可用的测试结果快照，明确复用旧运行结果或本次执行、实际通过数、历史版本范围及参考代码不参与识别的说明。核验记录由服务器生成，不由模型补写；旧报告缺少记录时提示重新生成，不将旧报告描述为已完成新增核验。
- AI 率分类：`[0,30)` 低生成倾向，`[30,50)` 部分生成倾向，`[50,80)` 较高生成倾向，`[80,100]` 高生成倾向（单位为百分比）。分类仅整理复核顺序；证据不足单列，不当作低 AI 率。
- 分类数量标签可直接点击，支持按分类／未完成项筛选、AI 率升降序或姓名排序，每页 25 份；切换筛选与排序回到第一页。完整区间标准按需展开。
- 汇总展示参与检测、已给出 AI 率、证据不足的数量与报告时间。识别开始后收起范围设置，可通过“修改范围”展开。
- 整批与单份详情均可下载独立 HTML 报告、打印／保存 PDF。报告包含全部提交快照、分类定义、结论、维度覆盖率（旧版自评）、原始代码、多维度代码依据、判断局限及失败／停止项，不受页面筛选和分页影响；不展示模型名称与调用次数。整批识别进行中禁用导出，结束或停止后可导出包含明确未完成标记的报告。
- 支持停止识别和重试未完成项；停止会取消当前请求，不再发起后续请求。成功结果（包含“证据不足”）保存到数据库，刷新、重新进入、切换检测类型或选择历史提交时读取已保存报告，不自动调用模型。
- 首次点击“开始 AI 识别”生成报告；“重新生成”显式调用模型，并立即清空本次范围内界面上的旧分数、结论和依据，只显示等待／生成进度，新结果逐份返回后展示。全班中有新提交时可用“生成未识别项”补齐。失败或停止不删除数据库中的旧报告，本次页面显示失败／停止状态；重新打开页面可读取数据库中保留的结果。
- 修改题面、参考实现或模型配置不会自动使报告失效，原分数、依据和生成时间保留，点击“重新生成”才更新。报告按提交编号保存，新提交不继承同一学生旧提交的报告。
- AI 率是基于模型维度分析、由固定规则综合的生成倾向评分，不是实际生成行数占比或校准后的概率，不应单独用于判定违规或评分。

接口仅作业所属教师可调用，提交必须属于该作业：

- `GET /api/v1/assignments/:id/ai-detection`：读取每名学生最新提交的已保存报告，返回 `{"results":[]}`；可带 `?submissionId=编号` 读取指定当前或历史提交。缺失报告不触发生成；读取旧报告不要求模型密钥可用。
- `POST /api/v1/assignments/:id/ai-detection`：请求体为 `{"submissionId":"提交编号","regenerate":false}`，已有报告则直接返回，缺失报告时生成并保存。显式传 `"regenerate":true` 才覆盖已有报告。保存成功后才返回新结果。

启动时自动创建 `ai_detection_records` 和 `ai_sample_banks` 表。后端从数据库加载代码，复用原有 DeepSeek 配置和 JSON 校验／重试客户端，无需新增服务配置。

### 五维度评分（dimensions-v8）

无需训练或本地模型；复用现有 DeepSeek 接口，已有同题样本时分析通常一次请求；首次逐份调用三次生成解答，各份成功立即保存，失败后从缺失处继续。各阶段结构或引用校验失败时各最多重试一次，沿用 temperature=0 和 JSON 输出模式。模型不生成总分或判断置信度；后端验证五维度、整数分数、证据强度、判断理由和逐字源码引用，再计算 AI 率。

| 维度 | 基础权重 | 分析范围 |
| --- | --- | --- |
| 题目与实现契合 task_fit | 20% | 实现是否出现与任务脱节的组合；题面约束和标准解法本身不作为来源证据 |
| 代码结构与表达 structure | 20% | 实现与组织方式的组合特征；规范命名、整洁格式和复杂程度不能单独定来源 |
| 注释与代码关系 comments | 20% | 解释与实现的关系、生成对话残留等；无可区分证据时不评分 |

| 同题 AI 样本匹配 sample_match | 20% | 模型对照三份完整样本和真实比对统计评分；没有连续匹配片段也评分，匹配率不直接作为维度分 |
| 学生历史与提交演变 history | 20% | 对照此前同学生同作业源码，引用具体变化及反向依据；大改或风格变化本身不是强证据 |

模型分别输出维度分、判断理由与证据强度；服务端根据证据强度计算实际占比和综合分。运行结果提供事实材料，历史维度使用实际提供的旧源码。

- 识别提示词采用正常、客观的直接判断策略（promptVersion=source-review-direct-v3）：根据实际材料逐维独立评分，不预设高分、不套用固定中间分、不刻意制造分差。理由直接写判断和具体事实，不输出含糊套话、反向解释或重复的参考性提醒。五个维度均省略 alternative，limitations 返回空数组；新报告不保存额外返回的 alternative。正常请求、样本评分重试和引用修复均使用该要求。
- dimensions-v8 采用动态占比：基础权重仍各为 20%，强／中／弱证据系数为 3／2／1。实际占比（百分数）= 基础权重 × 强度系数 ÷ 参与维度的加权权重合计 × 100。缺少材料的维度占比为 0；全部维度无法判断时不生成综合分。证据强度支持当前判断的方向，强证据既可以支持高分，也可以支持低分。
- 页面、权重环形图、维度详情和 HTML／打印报告统一显示服务端计算的实际占比，保留一位小数；计算使用完整精度。旧版报告继续展示原基础权重与原规则。更新并重启后端后，重新生成报告才使用新提示词和动态占比；读取旧报告不自动改用动态权重。
- 维度生成倾向值为 0–100 的整数，页面显示百分比：0–29 明显偏人工；30–49 略偏人工；50 方向接近；51–79 偏向 AI；80–100 明显偏 AI。按具体事实给出整数值，不先打十分制再乘十、不强行制造分差。未知用 null，不能用 0 或 50 代替。已评分维度须有判断理由和 weak/moderate/strong 证据强度，通常需 1–4 条引用；同题样本允许以三份完整源码及服务端比对统计作为材料依据（evidenceBasis=sample_comparison），没有连续匹配片段时 evidence=[]，仍由模型评分。强度独立于分数高低评估，并决定本维度的实际占比；0 分也可以有强证据，100% 也可以只有弱证据。
- 后端固定维度名、基础权重及强度系数，不接受模型提供的总分、实际占比、覆盖率或计分标记。已核验的引用可以用于多个维度的分析，不再因引用相同或行范围重叠排除维度。每个维度按其实际占比只计入一次，不因引用条数增加权重。公共框架和标准算法仍不能单独证明来源，由各维度分析说明。
- 有原始分析值和已核验依据的维度均参与综合结果，不因证据强弱、低分或引用复用排除。不再要求至少两个维度才出总分；没有任何可用分析值时才不生成综合结果。缺少材料或引用无法核验时标为“无法判断”，不据此捏造百分比或记为零分。
- 综合分 = Σ(维度生成倾向分 × 实际占比百分数) ÷ 100，保留一位小数。例如强证据维度 90 分、中等证据维度 60 分、弱证据维度 30 分时，实际占比分别为 50%、33.3%、16.7%，综合分为 70%。未知维度占比为 0，原始维度分不因强度改变。
- 维度覆盖率是参与维度基础权重之和，例如前两维度参与时为 40%；不代表证据真实度、置信度或识别准确率。页面同时展示可用维度数量、基础权重覆盖比例、实际占比和各维度证据强度。旧版 dimensions-v1/v2/v3 保留 4 分制，dimensions-v4 保留 10 分制，保留原快照与原规则，展示旧规则提示，显式重新检测后采用新规则。
- 新报告写入 scoringVersion、dimensions（含 effectiveWeight 实际占比）、coverage 和 aggregationNotes，随现有 JSON 报告保存，无需新增数据库字段。confidence 仅保留旧协议字段，新报告为 0 且页面不显示为置信度。旧报告不自动重新识别；原单次估计和 dimensions-v1 三维度报告均保留原结果，页面及导出提示显式重新生成。
- 已保存的 dimensions-v5 百分比报告在读取时使用原始已核验分析值按 dimensions-v6 重新汇总展示，恢复因跨维度去重被排除的分数。响应通过 recalculatedFromVersion 和汇总说明标识这一过程，不调用模型、不覆盖数据库原始快照，也不改变原识别时间。旧版 4 分制、10 分制报告保持原量表。
- dimensions-v7 及以前的报告保留原计分规则，dimensions-v8 仅用于新识别。旧报告缺失的样本评分须显式重新生成，不在读取时用匹配率、零分或固定中间分冒充新的模型分析。


### 同题 AI 样本与历史对照

- 每次识别先通过样本准备接口补齐本题三份样本，全部就绪后才逐份识别；后端单份接口也校验这一前提。样本生成、读取或保存失败时本批停止，保留已完成的样本和既有报告，不再让早期报告静默缺少样本、后期报告却使用新生成样本。
- “已比对三份样本，未找到符合条件的匹配片段”和“本报告未完成样本比对”分别展示。前者表示已加载并比较，但没有达到至少 20 个连续词元的匹配，不能理解为样本缺失，也不能据此推断人工来源。
- 当前代码按每段最多 12 行生成 currentEvidence 目录，模型通过 citationId 选择既有片段，服务器提取真实原文、缩进和行号。历史两侧分别使用 citationId 和 sourceCitationId，sourceId 必须是实际提供的旧版编号；每份旧源码同时提供片段目录。支持长文件中的重复代码，不依赖模型重抄源码或自行划定行号。样本引用使用已核验 matchId。兼容能严格核验的旧行号和逐字引用，额外提供的编造原文仍会被拒绝。
- 常规修正后引用仍失败时，只对出错维度另行调用模型重新分析，要求从服务器片段目录选择真实引用；已通过校验的其他维度保留。task_fit、structure 不能因定位技术错误被降级为无法判断。专门修复最多两次，仍不合法则返回错误且保留旧报告，不把残缺报告保存成成功结果。新报告通过 citationVersion=source-blocks-v1 标识定位协议，citationDiagnostics 保留最初校验失败的具体维度与原因，便于追查。

- 首次检测题目时，使用现有 DeepSeek 服务逐份生成直接、模块化及不同实现策略的三份完整解答；每份使用独立且至少8192 token的输出预算，不占用评分响应预算。识别 finish_reason=length 后拒绝保存截断代码，页面显示具体失败阶段。生成输入仅包含题目、语言、标题和公共框架，不含学生代码、隐藏用例或教师存档参考答案；后续样本可使用已生成的 AI 样本避免重复。样本未经过沙箱测试，不作为标准答案。
- 样本保存到 ai_sample_banks，按作业编号及内容指纹隔离。指纹包含标题、语言、题面、公共框架、服务地址、模型和生成规则版本；题目或模型变化后按新指纹生成，旧报告快照不变。修改存档参考答案不影响样本库。服务内同题并发生成合并，等待请求可取消；逐份成功后立即保存，并发写入仅允许样本数量增加；已成功的样本不因后续失败被清空。
- 使用现有 token-runs-v1 算法逐份对比当前代码与三份样本，自动排除公共框架，至少20个连续词元形成匹配片段，允许一致的一一对应标识符替换。每份最多提供前4个匹配片段，相似度和匹配词元数按完整结果计算。分析请求始终另行提供三份带行号的完整样本源码，零匹配时模型仍比较实现、说明差异与合理人工解释，独立给出维度分和证据强度；不得直接以最高匹配率计分。比对超预算或样本准备失败时返回明确错误，不静默使用不完整材料。
- 历史仅使用当前提交之前、同学生同作业最多三份代码；省略源码的版本不能作为评分来源。history 的证据须同时引用当前与历史代码。sample_match 如引用匹配片段，须使用服务端验证的 matchId，两侧原文由服务端提取；没有可用匹配引用时 evidence=[]，不影响基于整体样本比较的模型评分。模型漏给样本分数时要求其修正一次，仍缺失则报错且保留旧报告，不将成功响应中的样本维度降级为无法判断。
- 检测页直接展示“同题 AI 样本库”、已保存数量、生成/继续生成按钮和三份完整代码，不必打开学生报告才能找到。GET /assignments/:id/ai-samples 仅读当前题目指纹的样本，POST 同路径只生成缺失项；均仅作业所属教师可访问。页面生成中定期读取保存进度，失败消息持续显示。
- 页面和 HTML/PDF 报告展示两侧对照引用、样本比对记录、缺失材料原因、各维度有效分及实际覆盖率。缺少历史或样本时仍展示全部五个维度，但材料不足项不评分。五维度不改变来源判断的局限，不将匹配率当来源概率。


模型接收带原始行号的逐行源码；真实引用因行号偏移或行首／行末空白而未匹配时，仅在能唯一定位到源码（或与指定行范围一致）时修正行号并展示原始代码。不会修改字面量内部空白，不接受编造的代码或无法唯一定位的引用。

补充核验材料的范围：

- **运行结果**：仅使用本份不可变提交的结果；保存结果代表原评估时的用例，不声称已按当前用例重新验证。向模型和报告提供最多前 20 项结果，公开用例的输入、期望与实际输出各限制 2000 字节，编译信息限制 4000 字节；截断有明确标记，隐藏用例不提供输入和输出。失败用例可定位已发生的问题，未覆盖的恢复、快照等边界仍只能作为静态推测，不自动生成或执行模型建议的额外用例。
- **历史版本**：仅取同学生、同作业且早于本份提交的最近三份，时间相同时按编号判定先后，不读取未来版本或其他学生代码。每份超过 20000 字节时只提供编号和时间并标记省略，不截取部分代码后冒充完整版本。平台提交记录不等于完整编辑过程、AI 对话或生成历史。
- **参考代码**：选填且仅教师可见，目前仅存档，不传给模型，不进行参考答案比对；填写、清空或修改都不影响新生成报告。

模型必须区分已验证事实、未覆盖行为和来源解释；测试成败、代码缺陷、版本大改或与详细题面吻合本身不能直接证明 AI 来源。已提供运行结果后，若模型仍输出常见的相反局限描述，会进入原有格式校验重试；重试后仍矛盾则不保存新报告。仍保留真实的过程记录缺失与来源不可区分等限制。

报告读取或保存失败返回 500（`ai_storage_error`），原有报告保留。生成时，代码为空或超过 `max_code_bytes` 返回 422，未配置密钥返回 503，服务超时返回 504，上游失败或重试后结果仍无效返回 502。错误响应的 `code` 区分 `ai_timeout`、`ai_evidence_mismatch`、`ai_invalid_response` 和 `ai_service_error`，页面显示具体原因。全班识别遇到登录、权限或服务配置错误会停止后续调用，普通单份失败保留错误并继续。

AI 识别前端专项检查：`npm --prefix web run test:ai-detection`，覆盖分类边界、筛选排序、完整导出、HTML 转义、模型信息隐藏、下载与打印生命周期。

## 相似度比对

- **全班查重**：按提交时间取每名学生最新一次代码；时间相同时取编号最大的提交，不因评估未完成而回退旧版本。
- **指定两份提交**：可选择同一次作业的任意两份历史提交，A/B 顺序与选择一致。
- **公共代码排除**：点击“设置公共代码”（已有设置时为“修改公共代码”），在弹窗中粘贴教师发给学生的框架、示例代码。保存后应用，取消不改变原设置及检测结果；保存修改后需重新检测，留空保存可移除设置。按至少 8 个连续原始词元匹配，排除空白、注释差异后相同的公共片段。请勿填入完整参考答案。此设置仅用于本次检测，不保存为作业配置。
- **检测说明**：点击页面标题旁的“检测说明”，在弹窗中查看算法口径、判读限制与计算预算。
- **证据查看**：配对按相似度降序排列，每页 25 组。点击“查看对应代码”，或点击片段定位双方行号。颜色标记的是相似片段所在行范围，范围内的空白、注释和其他字符不单独计为重复证据。
- **导出**：“下载 HTML 检测报告”生成可离线打开的报告；“打印 / 保存 PDF”调用浏览器打印功能，选择“另存为 PDF”。报告包含本次参与提交的编号、学生信息、时间、有效词元数、排除量、算法版本、公共代码、全部发现的相似配对及高亮片段，不受页面相似度筛选影响。

## 检测方法

相似度后显示默认区间标签，页面、HTML 报告及打印 / PDF 报告使用相同规则：

| 相似度区间 | 标签 |
| --- | --- |
| 0% ≤ 相似度 < 30% | 低相似 |
| 30% ≤ 相似度 < 50% | 部分相似 |
| 50% ≤ 相似度 < 80% | 疑似抄袭 |
| 80% ≤ 相似度 ≤ 100% | 高度疑似抄袭 |

区间用于安排教师复核优先级，相似度不代表抄袭概率。阈值为产品默认提示，未经真实班级标注数据校准。判断时仍需结合公共代码、题目解法限制及匹配证据，低相似不等于证明独立完成。

`token-runs-v1` 在服务器本地执行，不调用 DeepSeek 或其他模型，不执行学生代码。

1. 对 Go、Python、Java、C++ 代码提取词元，忽略空白、注释、导入和包声明；保留运算符与字面量。Python 保留每行缩进宽度。
2. 排除教师本次提供的公共代码，不使用隐藏的参考实现，也不根据全班出现频率自动排除代码。
3. 使用滚动哈希检索候选连续片段，再逐词元验证；哈希碰撞本身不会形成证据。
4. 至少 20 个连续词元才形成证据。允许片段内一致且一一对应的标识符替换，区分“代码词元一致”与“标识符替换后匹配”。这不等同于语法树或语义等价检测。
5. 从 A 到 B 按代码顺序贪心选择匹配片段；同一词元在同一配对内仅计一次。复杂重复或重排代码中的结果可能受 A/B 顺序影响。两份代码中保留原始行号用于展示。

计算方式：

- A 覆盖率 = 匹配词元数 / A 的有效词元数。
- B 覆盖率 = 匹配词元数 / B 的有效词元数。
- 相似度 = 2 × 匹配词元数 / 双方有效词元总数。
- 有效内容不足 20 个词元时页面明确提示，不作“已证明独立完成”的结论。

结果只作为教师复核线索，不自动判断抄袭、不推断复制方向、不修改成绩。不能识别全部结构改写、语义等价、跨语言复制或 AI 生成代码，也不查询互联网、其他作业或历史班级。

## 接口与限制

教师专用：`POST /api/v1/assignments/:id/similarity`。

```json
{"submissionIds": ["7", "8"], "template": ""}
```

`submissionIds` 为空数组或省略时为全班模式；指定时必须为两个不同、属于本次作业的提交编号。后端先校验作业所有权，再读取代码；学生和其他教师无法访问。

每批最多 200 人；单份最多 200000 字节、20000 个词元；整批最多 300000 个词元；公共代码最多 64000 字节。请求体上限 128 KiB，处理超时 20 秒，并设计算预算。超限返回明确错误，建议缩小为两份比对，不返回残缺的检测结果。

相似度比对按需执行，结果不写入数据库；页面刷新后需要重新比对，需留存时请导出报告。AI 生成识别报告则按上文持久化保存。

## 验证

- `GOCACHE=/private/tmp/codeeval-go-cache go test ./...`（在 `server/` 下）。
- `npm run test:similarity` 与 `npm run build`（在 `web/` 下）。

后端测试覆盖四种语言的注释／排版、改名映射、行号、重复模板排除、重复片段不重复计数、最小长度、字面量与缩进、规模限制、取消请求，以及教师权限与查询范围。浏览器验证使用本地合成学生代码和真实查重算法，不读取或修改真实学生数据。
