# 代码检测：相似度比对与 AI 生成识别

[文档首页](README.md) · [项目首页](../README.md)

## 使用方式

教师打开“作业”，在自己发布的作业操作区点击“代码检测”，选择“相似度比对”或“AI 生成识别”。

## AI 生成识别

- **全班识别**：每名学生取最新一次提交，逐份调用现有 DeepSeek 服务；时间相同时取编号最大的提交。
- **单份识别**：可选择当前或历史提交。识别独立于作业的 AI 评分开关，不执行沙箱测试，不改变成绩。
- 展示 AI 率估计、判断置信度、结论、原始代码引用与行号和判断局限。模型名称与调用次数不在页面展示。证据不足时展示“证据不足”，不生成百分比。
- AI 率分类：`[0,30)` 低生成倾向，`[30,50)` 部分生成倾向，`[50,80)` 较高生成倾向，`[80,100]` 高生成倾向（单位为百分比）。分类仅整理复核顺序；证据不足单列，不当作低 AI 率。
- 分类数量标签可直接点击，支持按分类／未完成项筛选、AI 率升降序或姓名排序，每页 25 份；切换筛选与排序回到第一页。完整区间标准按需展开。
- 汇总展示参与检测、已给出 AI 率、证据不足的数量与报告时间。识别开始后收起范围设置，可通过“修改范围”展开。
- 整批与单份详情均可下载独立 HTML 报告、打印／保存 PDF。报告包含全部提交快照、分类定义、结论、置信度、原始代码、代码依据、判断局限及失败／停止项，不受页面筛选和分页影响；不展示模型名称与调用次数。整批识别进行中禁用导出，结束或停止后可导出包含明确未完成标记的报告。
- 支持停止识别和重试未完成项；停止会取消当前请求，不再发起后续请求。成功结果在当前页面内保留，切换检测类型或离开页面后需重新识别，不写入数据库。
- AI 率是模型对整份代码生成倾向的主观估计，不是实际生成行数占比或校准后的概率，不应单独用于判定违规或评分。

接口为 `POST /api/v1/assignments/:id/ai-detection`，请求体为 `{"submissionId":"提交编号"}`。仅作业所属教师可调用，提交必须属于该作业。后端从数据库加载代码，复用 `deepseek.base_url`、`api_key`、`model`、`timeout_seconds`、`max_tokens`、`max_code_bytes` 和现有 JSON 校验／重试客户端，无需新增服务配置。

每次识别都重新调用模型，不缓存或复用历史检测结果。每份提交通常调用模型一次，结构或引用校验失败时最多调用两次。检测沿用 `temperature: 0`、关闭思考和 JSON 输出模式；提示词固定证据判读顺序和四个区间的依据要求，同一事实不重复加权，不按代码长度、格式或注释数量直接加分；证据不足时仍返回空百分比。参数和判读标准旨在减少模型判断的随意性，不能保证每次结果完全一致，也不构成准确率校准。

模型接收带原始行号的逐行源码；真实引用因行号偏移或行首／行末空白而未匹配时，仅在能唯一定位到源码（或与指定行范围一致）时修正行号并展示原始代码。不会修改字面量内部空白，不接受编造的代码或无法唯一定位的引用。

代码为空或超过 `max_code_bytes` 时返回 422，未配置密钥时返回 503，服务超时返回 504，上游失败或重试后结果仍无效时返回 502。错误响应的 `code` 区分 `ai_timeout`、`ai_evidence_mismatch`、`ai_invalid_response` 和 `ai_service_error`，页面显示对应的具体原因。全班识别遇到登录、权限或服务配置错误会停止后续调用，普通单份失败保留错误并继续。

AI 识别前端专项检查：`npm --prefix web run test:ai-detection`，覆盖分类边界、筛选排序、完整导出、HTML 转义、模型信息隐藏、下载与打印生命周期。

## 相似度比对

- **全班查重**：按提交时间取每名学生最新一次代码；时间相同时取编号最大的提交，不因评估未完成而回退旧版本。
- **指定两份提交**：可选择同一次作业的任意两份历史提交，A/B 顺序与选择一致。
- **公共代码排除**：点击“设置公共代码”（已有设置时为“修改公共代码”），在弹窗中粘贴教师发给学生的框架、示例代码。保存后应用，取消不改变原设置及检测结果；保存修改后需重新检测，留空保存可移除设置。按至少 8 个连续原始词元匹配，排除空白、注释差异后相同的公共片段。请勿填入完整参考答案。此设置仅用于本次检测，不保存为作业配置。
- **检测说明**：点击页面标题旁的“检测说明”，在弹窗中查看算法口径、判读限制与计算预算。
- **证据查看**：配对按相似度降序排列，每页 25 组。点击“查看对应代码”，或点击片段定位双方行号。颜色标记的是相似片段所在行范围，范围内的空白、注释和其他字符不单独计为重复证据。
- **导出**：“下载 HTML 检测报告”生成可离线打开的报告；“打印 / 保存 PDF”调用浏览器打印功能，选择“另存为 PDF”。报告包含本次参与提交的编号、学生信息、时间、有效词元数、排除量、算法版本、公共代码、全部发现的相似配对及高亮片段，不受页面相似度筛选影响。

## 检测方法

相似度后显示默认区间标签，页面、HTML 报告及打印 / PDF 报告使用相同规则：

| 相似度区间 | 标签 |
| --- | --- |
| 0% ≤ 相似度 < 30% | 低相似 |
| 30% ≤ 相似度 < 50% | 部分相似 |
| 50% ≤ 相似度 < 80% | 疑似抄袭 |
| 80% ≤ 相似度 ≤ 100% | 高度疑似抄袭 |

区间用于安排教师复核优先级，相似度不代表抄袭概率。阈值为产品默认提示，未经真实班级标注数据校准。判断时仍需结合公共代码、题目解法限制及匹配证据，低相似不等于证明独立完成。

`token-runs-v1` 在服务器本地执行，不调用 DeepSeek 或其他模型，不执行学生代码。

1. 对 Go、Python、Java、C++ 代码提取词元，忽略空白、注释、导入和包声明；保留运算符与字面量。Python 保留每行缩进宽度。
2. 排除教师本次提供的公共代码，不使用隐藏的参考实现，也不根据全班出现频率自动排除代码。
3. 使用滚动哈希检索候选连续片段，再逐词元验证；哈希碰撞本身不会形成证据。
4. 至少 20 个连续词元才形成证据。允许片段内一致且一一对应的标识符替换，区分“代码词元一致”与“标识符替换后匹配”。这不等同于语法树或语义等价检测。
5. 从 A 到 B 按代码顺序贪心选择匹配片段；同一词元在同一配对内仅计一次。复杂重复或重排代码中的结果可能受 A/B 顺序影响。两份代码中保留原始行号用于展示。

计算方式：

- A 覆盖率 = 匹配词元数 / A 的有效词元数。
- B 覆盖率 = 匹配词元数 / B 的有效词元数。
- 相似度 = 2 × 匹配词元数 / 双方有效词元总数。
- 有效内容不足 20 个词元时页面明确提示，不作“已证明独立完成”的结论。

结果只作为教师复核线索，不自动判断抄袭、不推断复制方向、不修改成绩。不能识别全部结构改写、语义等价、跨语言复制或 AI 生成代码，也不查询互联网、其他作业或历史班级。

## 接口与限制

教师专用：`POST /api/v1/assignments/:id/similarity`。

```json
{"submissionIds": ["7", "8"], "template": ""}
```

`submissionIds` 为空数组或省略时为全班模式；指定时必须为两个不同、属于本次作业的提交编号。后端先校验作业所有权，再读取代码；学生和其他教师无法访问。

每批最多 200 人；单份最多 200000 字节、20000 个词元；整批最多 300000 个词元；公共代码最多 64000 字节。请求体上限 128 KiB，处理超时 20 秒，并设计算预算。超限返回明确错误，建议缩小为两份比对，不返回残缺的检测结果。

检测按需执行，结果不写入数据库；页面刷新后需要重新检测，需留存时请导出报告。无需数据库迁移。

## 验证

- `GOCACHE=/private/tmp/codeeval-go-cache go test ./...`（在 `server/` 下）。
- `npm run test:similarity` 与 `npm run build`（在 `web/` 下）。

后端测试覆盖四种语言的注释／排版、改名映射、行号、重复模板排除、重复片段不重复计数、最小长度、字面量与缩进、规模限制、取消请求，以及教师权限与查询范围。浏览器验证使用本地合成学生代码和真实查重算法，不读取或修改真实学生数据。
