## 1. 设计目标

CodeEval 应当像一件可靠、安静、可以每天使用的教学工具。界面需要帮助教师快速处理课程事务，也需要让学生看懂评分依据和下一步改进方向。

设计优先级从高到低为：

1. 信息是否清楚、可判断、可操作
2. 评分和评估过程是否可信、可追溯
3. 教师和学生是否能快速找到下一步动作
4. 界面是否一致、易学、适合长期使用
5. 品牌表达是否克制而有辨识度

### 设计原则

#### 1. 任务优先，不做口号型首页

首屏优先展示待处理事项、截止时间、评估状态和异常情况。避免用大面积 Hero、欢迎语或装饰性口号占据核心空间。

#### 2. 证据优先，不神化 AI

AI 是评估方法之一，不是界面的主角。展示结果时先说结论，再说明测试、规则、代码事实和评分依据。柔和渐变用于页面氛围与导航层次，评分证据保持清晰、实色和可读，不用特效代替信息。

#### 3. 少用容器，多用结构

不要让每一组内容都变成独立大卡片。优先使用标题层级、留白、分割线、表格和列表组织信息。卡片只用于需要明确边界或独立操作的内容。

#### 4. 状态必须可以被快速扫读

开放、已截止、评估中、失败、待复核等状态使用一致的颜色、标签和文字。不能只依赖颜色表达状态。

#### 5. 桌面高效，移动端完整

桌面端强调信息密度和批量操作；移动端重新组织内容，而不是把桌面表格塞进横向滚动区域。

## 2. 视觉方向

### 1.15 查重证据弹窗

- 沿用 1.14 的白色、淡蓝紫顶部、墨蓝正文、灰色边界与 Dark+ 代码黑灰配色；字号与全局字体保持一致。
- 报告先呈现汇总与配对列表，点击“查看代码证据”才打开弹窗，不自动展开第一组。布局为 `[标题、说明、关闭] → [配对与匹配摘要 | 自动换行] → [片段导航] → [提交 A | 提交 B]`；手机按 A、B 纵向显示。
- 片段定位、语法高亮、复制与换行保持可用；关闭后返回原列表位置和触发按钮。弹窗沿用原生焦点约束、Esc 与遮罩关闭，单次打开只呈现选中的配对。
- 审视：复用测试详情的窗口语言，代码对照保留宽屏空间；不添加重复摘要卡或自动弹出，证据与报告阅读各有明确入口。

### 1.14 测试用例详情（其余界面继续沿用 1.13）

- 色彩：白 #ffffff、正文墨蓝 #182238、边界灰 #dfe5ee、通过青 #167a78、失败红 #b34553、代码黑灰 #1e1e1e。玻璃与蓝紫光感只用于弹窗顶部，输入输出使用稳定实色。
- 字体：沿用 Avenir Next / PingFang SC；标题 21px、用例名 14px、辅助信息 12–13px；输入输出使用 DM Mono / SFMono-Regular / Consolas 13px，保留空格与换行。
- 布局：全部左对齐；`[标题与说明] → [通过数量、语言 | 全部 / 未通过] → [用例序号、名称、状态 | 耗时、退出码] → [输入] → [期望输出 | 实际输出]`。窄屏输出纵向排列，长文本在容器内换行或滚动。
- 原则：边界服务于输入与输出对照，失败信息使用文字、图标和语义色；隐藏用例不展示输入输出或可能包含内容的原始错误。保留弹窗键盘、焦点和关闭行为，筛选即时反馈。
- 审视：不增加装饰性指标卡、环形进度或循环动画；把辨识度放在清楚的深色输出对照上，用留白与排版区分层次，避免多层同款卡片。

### 1.13 当前全局实施方案

- 保留白色、蓝紫青柔和光晕、玻璃面板与 Dark+ 代码区；不改为纯灰白界面。
- 色彩继续采用白 #ffffff、墨蓝 #182238、操作蓝 #4f60dc、品牌紫 #8b5cce、通过青 #167a78、提醒琥珀 #956010。课程按顺序染色改为统一操作蓝，已选课程使用通过青；平均分与复核提示按实际状态着色。
- 登录页保留主标题、课程能力和代码示例，去掉重复眉题、表单装饰图标、表单下方与页脚的宣传句。说明改为直接表达课程用途；登录表单保留唯一注册入口，注册表单保留唯一返回登录入口。
- 标题与正文保留原字体体系，辅助文字以 12–13px 为主，代码正文使用 12px；对齐、间距与输入边界保持稳定。主标题完整深色，不另加彩色强调词。
- 布局保持 `[品牌与导航] → [标题、能力与代码示例 | 账号表单]`；移动端保持 `[品牌] → [简短说明] → [表单]`。
- 操作反馈统一为 160–200ms，页面入场 320ms；保留游标闪烁、加载、复制成功等有明确含义的动效。取消数字滚动、逐行入场、按钮扫光与通用卡片浮起。
- 审视：精简来自重复宣传、按顺序上色与多层入场的模板感，同时保留用户选定的玻璃渐变视觉，不做整套主题替换。

### 1.12 历史恢复方案

- 按用户确认恢复本聊天前一版视觉：白色底、蓝紫青与柔桃光晕、半透明玻璃导航和登录面板，以及多色指标、课程图标和截止卡片。
- 登录首屏恢复“每一次提交，都有迹可循”、课程能力标签、代码示例与反馈说明；移动端简化品牌区并隐藏详细代码示例，保持表单可用。
- 登录示例的装饰游标以 1.1 秒周期闪烁；启用“减少动态效果”时隐藏游标。
- 登录页只保留表单下方一个“创建账号”入口，顶部不重复展示。
- 工作台恢复原数据呈现和轻量反馈动效；所有状态继续使用文字和一致的语义色。
- 代码编辑、只读查看、登录示例和查重仍统一使用 VS Code Dark+，不恢复旧墨绿或深蓝底色。
- 当前全局颜色、圆角与阴影以 `web/src/tokens.css` 为准，玻璃与渐变以 `web/src/prism.css` 和登录样式为准。

### 1.11 历史简化方案（已由 1.12 替代）

- 色彩：白 `#ffffff`、浅灰 `#f5f7fa`、深蓝墨 `#182238`、操作蓝 `#4f60dc`、边界灰 `#dfe5ee`、通过青 `#167a78`。紫色只保留于品牌标识，不按指标或课程顺序分配装饰色。
- 字体：Avenir Next / PingFang SC 用于标题、正文和数字；SFMono-Regular / Consolas 用于代码、文件名及输入输出。数字使用等宽数字特性，不滚动计数。
- 布局：桌面保持左侧产品代码示例、右侧账号表单；标题、说明、表单均左对齐。移动端保留简短说明和完整表单，避免重复导航到隐藏示例。

```text
品牌                           创建账号
提交代码，看懂反馈。           登录 CodeEval
课程用途说明                   账号 / 密码
solution.py                    进入工作台
测试输入 / 预期 / 运行结果      演示账号
```

- 原则：代码示例是登录首屏唯一强视觉元素；反馈用具体的输入和输出解释。工作台以真实课程、提交和截止时间建立辨识度，普通面板使用稳定白底和轻边界，浮层才用明显阴影。
- 审视：取消通用的彩色指标图标块、整页多色光晕、截止卡同心圆、按钮扫光、重复眉题和宣传文案；保留花括号标识、Dark+ 代码主题、清晰状态色和原有功能。卡片圆角 12px，表单面板 18px，控件 8px。
- 动效：仅保留整体页面轻量切换及用户操作反馈；指标、列表和图表不逐项入场。键盘焦点、触控尺寸和减少动态效果规则继续生效。

### 关键词

- 克制
- 通透
- 清晰
- 可信
- 高信息密度
- 轻盈但有秩序

### 避免的视觉语言

- 大面积深色 Hero
- 荧光色作为主要品牌特征
- 无意义的英文大写眉题
- 无差别使用超大圆角和层层嵌套卡片
- 导致正文对比度不足的透明效果与高饱和渐变
- `</>`、`⌂`、`▤` 等字符充当正式图标
- 为了“高级感”而降低文字对比度
- 到处使用“智能”“AI 驱动”“赋能”等宣传型表达

### 整体气质

以白色为底，雾蓝、鸢尾紫、浅青与柔桃色构成低饱和光晕。参考 GitHub 未登录首页的大留白、清晰标题与产品示例呈现；保留 CodeEval 自己的花括号标识和编程课程内容。玻璃拟态仅用于导航、登录容器及独立面板，正文保持深色文字和稳定浅色底。工作台保留连续数据栏与非对称内容布局，四种指标分别用蓝、紫、青、琥珀色区分，状态仍同时提供文字。

本轮设计方案：
- 统一规则：旧灰绿装饰、输入边界、进度条、骨架屏、发布摘要与评估背景改用蓝紫或冷灰共享变量；成功状态用清晰青色。代码区单独采用 Dark+ 中性黑灰，保留其标准注释绿与数值绿。
- 色彩：白 `#ffffff`、深蓝墨 `#182238`、蓝 `#4f60dc`、紫 `#8b5cce`、青 `#18868a`、柔桃 `#f7d9cf`。
- 字体：系统 Avenir Next / PingFang SC 用于界面，DM Mono 用于代码与数字；标题使用完整深色文字。
- 布局：桌面顶部通透导航；左侧标题与 Dark+ 代码示例，右侧玻璃登录面板；移动端依次显示品牌、简短标题和表单。
- 结构：`[品牌 / 产品入口 / 注册] → [标题 + 代码预览 | 登录表单] → [课程能力说明]`；工作台沿用真实数据与现有导航。
- 审视：取消原先的整块灰绿分栏、编号眉题和倾斜深色示例，不堆叠装饰卡片。渐变集中于背景与产品示例外围，表格、评分与编辑器保持可读。

使用规则：

- 页面背景使用 `canvas`，主要内容使用 `surface`。

- 分数颜色仅用于提示区间，数字本身同时保留文字含义。
- 绿色用于通过、高分和开放等正向状态；警告使用棕金色，失败使用砖红色，并同时提供状态文字。
- 评估总分使用紧凑圆角数据块，标签在上、分数在下；不使用圆形仪表盘承载横向的“分数 / 满分”文本。
- “评估失败”和“低分”不是同一语义，不共用一种状态标签。

### 3.2 字体

```css
--font-sans: "Avenir Next", "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "DM Mono", "SFMono-Regular", Consolas, monospace;
```

- 产品文字统一使用无衬线字体。
- 代码、语言标识、测试输入输出使用等宽字体。
- 英文和数字使用 Inter；中文跟随系统中文字体。
- 不再用 Arial 覆盖全局字体。

### 3.3 字号

| Token | 字号/行高 | 用途 |
| --- | --- | --- |
| Display | 32/40 | 页面核心数字或登录页品牌句，少量使用 |
| H1 | 28/36 | 页面标题 |
| H2 | 20/28 | 区块标题 |
| H3 | 16/24 | 卡片或列表组标题 |
| Body | 14/22 | 默认正文 |
| Small | 12/18 | 辅助说明、元数据 |
| Micro | 11/16 | 标签内部，禁止用于长句 |

移动端 H1 为 `24/32`。正文最小字号为 12px，表单和主要列表不得低于 14px。

### 3.4 间距

使用 4px 基础网格：

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-8: 32px;
--space-10: 40px;
--space-12: 48px;
```

- 页面区块间距：32px
- 区块标题与内容：16px
- 表单字段间距：20px
- 列表行垂直内边距：14–16px
- 不因内容少而人为放大卡片高度

### 3.5 圆角和阴影

```css
--radius-sm: 8px;
--radius-md: 12px;
--radius-lg: 18px;
--shadow-card: 0 10px 28px rgb(16 24 40 / 6%);
--shadow-popover: 0 12px 34px rgb(16 24 40 / 12%);
--shadow-dialog: 0 20px 54px rgb(16 24 40 / 16%);
```

- 输入框、按钮：7–8px；搜索框与分段控件使用小圆角，减少胶囊堆叠。
- 卡片、面板：12px；移动端独立任务卡使用 10–12px。
- 对话框：18px。
- 普通卡片使用极弱边框和一级软阴影，不叠加多层卡片。
- 强阴影只用于弹层、菜单和悬浮导航。

### 3.6 图标

- 统一使用一套 20px 线性 SVG 图标。
- 常规描边宽度 1.75px。
- 图标与文字同时出现时，图标不承担唯一语义。
- 不使用 Unicode 字符模拟图标。
- 产品标记统一使用花括号与中心点；登录页、工作台和浏览器图标共用蓝紫渐变 favicon.svg。

### 3.7 动效

动效用于解释界面状态变化，不作为装饰。整体感受应当轻、快、连续，避免大幅位移、弹跳和长时间等待。

```css
--motion-fast: 140ms;
--motion-base: 220ms;
--motion-slow: 320ms;
--ease-standard: cubic-bezier(.2, 0, 0, 1);
--ease-emphasized: cubic-bezier(.16, 1, .3, 1);
```

- 页面和详情切换：使用 `220–320ms` 的淡入与最多 `8px` 纵向位移，不做横向飞入。
- 按钮、标签和导航选中态：颜色与背景使用 `140–220ms`；按下时允许缩放至 `0.975–0.98`。
- 列表和卡片：首次进入允许不超过 `64ms` 的轻量错峰；禁止逐项长时间瀑布动画。
- 折叠内容：高度、透明度和箭头方向同步变化，避免内容瞬间出现或消失。
- 输入聚焦、边框和阴影变化使用标准缓动，不使用 `transition: all`。
- 代码编辑器内部不增加干扰输入的装饰动画。
- 必须尊重 `prefers-reduced-motion: reduce`；开启后将动画与平滑滚动降至近乎即时。

## 7. 核心组件规范

### 7.1 Button

类型：

- Primary：每个页面或弹层最多一个
- Secondary：普通操作
- Tertiary：低强调文字操作
- Danger：删除、关闭提交等危险操作

尺寸：

- 默认高度 36px
- 大尺寸 40px，仅用于登录和关键提交
- 移动端触控区域不小于 44×44px

加载时保留按钮宽度，显示 spinner 和进行中的动词。禁用态不能用于替代错误解释。

### 7.2 Status Badge

所有状态使用“颜色 + 文本”。

| 类别 | 示例 |
| --- | --- |
| 成功 | 已完成、测试通过、已评估 |
| 警告 | 即将截止、待复核、部分通过 |
| 危险 | 运行失败、评估失败、已逾期 |
| 信息 | 排队中、运行中、评估中 |
| 中性 | 草稿、已关闭、未提交 |

标签不得使用纯大写英文。

### 7.3 Table

- 表头固定在滚动容器顶部。
- 行高不低于 52px。
- 主列左对齐，数字列右对齐，状态列左对齐。
- 行点击与内部按钮区域不能互相冲突。
- 排序列必须显示排序方向。
- 无数据、加载失败、筛选无结果分别设计。

### 7.4 Form

- 标签位于控件上方。
- 必填信息使用文字说明或统一标记。
- 帮助文字紧邻字段。
- 错误在字段下方出现，并说明如何修正。
- 不使用 placeholder 替代标签。
- 日期、分数、次数等字段必须有格式或范围说明。

### 7.5 Empty State

空状态包含：

1. 发生了什么
2. 用户可以做什么
3. 可选的单个操作

不使用抽象插画填充空间。加载中使用骨架屏或行内进度，不使用空状态组件。

### 7.6 Feedback Block

反馈块类型：总结、优点、改进、证据、教师备注。

- 默认使用白色背景和左侧语义色标识。
- 不使用整块浅红/浅绿背景堆叠。
- 每条反馈尽量对应一个可定位的事实。
- 改进项使用明确动词开头，例如“检查空输入”“补充复杂度说明”。

### 7.7 Toast 与 Alert

- Toast 用于短暂成功反馈，不承载关键错误。
- Alert 用于页面级错误、权限问题或无法继续的状态。
- 错误信息包含原因、影响和恢复操作。

## 8. 文案规范

### 语气

清楚、直接、尊重用户专业判断。避免过度热情、拟人化和营销语言。

推荐：

- `3 份提交等待查看`
- `测试运行失败，请检查标准输入格式。`
- `评估依据不足，建议教师复核。`
- `发布作业`

避免：

- `今天也一起把反馈做得更好。`
- `AI 正在为你赋能`
- `太棒了！你的代码表现非常出色！`
- `COURSE OVERVIEW`
- `AI ASSESSMENT`

### 命名统一

- 一级导航使用“提交”，页面标题可使用“提交记录”。
- 教师创建内容统一称为“发布作业”，未发布状态称为“草稿”。
- 系统执行代码称为“运行”或“测试运行”。
- 综合生成结果称为“评估”，人工动作称为“复核”。
- 不混用“评分”“评价”“评测”表示同一流程。

### 时间与数字

- 同一年：`9 月 18 日 17:05`
- 跨年：`2027 年 1 月 3 日 09:00`
- 相对时间只用于辅助，例如 `2 小时前`，同时可查看准确时间。
- 分数写作 `92 / 100`，不要仅展示孤立的 `92`。
- 数量使用完整单位，例如 `3 份提交`、`2 项作业`。

## 9. 交互与状态

每个数据页面必须覆盖：

1. 首次加载
2. 加载成功
3. 空数据
4. 筛选无结果
5. 请求失败
6. 权限不足
7. 局部更新中
8. 更新成功或失败

### 评估流程状态

```text
已提交 → 排队中 → 运行测试 → 静态分析 → 模型评估 → 已完成
                      └──────────────→ 失败 / 待复核
```

- 用户看到的状态必须来自真实流程阶段。
- 不确定耗时时使用阶段状态，不展示虚假的百分比进度。
- 重新评估不会覆盖历史结果，应保留版本和时间。

### 危险操作

关闭提交、删除草稿、重新评估等操作必须说明影响范围。确认框按钮使用具体动词，例如“关闭提交”，不用“确定”。

## 10. 可访问性

- 正文与背景对比度达到 WCAG AA。
- 所有操作支持键盘访问。
- 焦点环清晰可见，不因鼠标操作永久移除。
- 图标按钮必须提供可访问名称和 Tooltip。
- 状态不只依赖颜色。
- 表单错误通过 `aria-describedby` 与字段关联。
- 动态评估状态通过适度的 live region 通知，不频繁打断。
- 尊重 `prefers-reduced-motion`。
- 页面缩放至 200% 时仍可完成主要任务。

## 11. 动效

动效只用于解释状态变化：

- 按钮与菜单：120–160ms
- 面板与对话框：180–220ms
- easing：`cubic-bezier(0.2, 0, 0, 1)`
- 骨架屏使用低对比度渐变
- 禁止大面积入场动画、无限数字滚动和装饰性浮动；数字允许首次进入时在 500ms 内平稳到位
