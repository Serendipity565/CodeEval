# 演示数据

[文档首页](README.md) · [项目首页](../README.md)

本文说明内置评分快照、课程与选课演示数据、演示账号及导出方法。表结构与迁移机制见[数据库设计](database.md)。

## 开关行为

- `seed.enabled: true`：在 AutoMigrate 后从真实快照补充缺失的演示用户、作业和提交，再补入课程、选课关系与未提交学生。
- `seed.enabled: false`：执行表结构和已有作业课程归属迁移，不补入演示账号、课程或评分快照。
- 作业的 `llm_evaluation_enabled: true`：学生提交时调用 `deepseek-v4-flash`。
- 作业的 `llm_evaluation_enabled: false`：学生提交时执行本地规则评估。

## 数据来源

评分和提交快照来自 **2026-10-18 在本地网页上的实际操作**：注册教师和学生、发布 C++ 作业、填写参考实现及测试、学生逐个提交、远程 Docker 沙箱执行、DeepSeek 模型评分。没有手填的演示总分或伪造教师复核。

原始快照为 [`server/internal/store/fixtures/recorded_seed.json`](../server/internal/store/fixtures/recorded_seed.json)，由 `go:embed` 随后端编译。`SeedMockData` 读取并校验快照，再按账号、作业与学生关系幂等导入。导入不调用模型，也不重新运行代码。

课程与选课演示数据另定义在 [`server/internal/store/course_seed.go`](../server/internal/store/course_seed.go)。这部分为构造的功能演示数据，包含未提交学生与第二位教师，不声称来自上述实际操作，也不增加任何提交、评分或教师复核。

当前内置快照已将首位学生账号统一为 `student01`，原始代码、评分和时间保持不变。

## 课程与选课场景

全新数据库启用 seed 后，包含 2 位教师、8 位学生、3 门课程、11 条选课关系和原来的 6 份提交：

| 课程 | 教师 | 初始选课学生 | 作业与名单场景 |
| --- | --- | --- | --- |
| C++ 程序设计 | `teacher`（李老师） | `student01`–`student08`，共 8 人 | 原始两数之和作业：已提交 6 人，未提交 2 人，提交率 75% |
| 数据结构与算法 | `teacher`（李老师） | `student01`、`student02`、`student07`，共 3 人 | 尚无作业，可直接查看 3 人名单并发布第一项作业 |

- 用 `student01` 登录：“全部课程”有 3 门，“已选课程”有 2 门；Python 课程可用于体验选课。
- 师生课程列表均可按课程名称、授课教师或说明搜索。搜索框位于课程 tab 右侧：“全部课程”输入 `Python` 初始匹配 1 门，“已选课程”输入 `Python` 初始无匹配；两处分别保存各自的关键词，清空搜索后恢复当前范围的课程列表。
- 用 `student07` 或 `student08` 登录：可以查看并提交原来的 C++ 作业；教师的未提交名单初始包含这两人。
- 用 `teacher` 登录：可以查看本人课程的选课学生与 75% 的初始提交率；`teacher02` 只管理自己的 Python 课程。
- 新增选课时间为首次补入记录的时间；重复初始化不会改写已有选课时间。

已有数据库中，如果原始演示作业已归属某门课程，则保留其课程归属，并为该课程补齐上述 8 人选课关系。旧版本自动生成、名称和说明均未经教师修改的默认课程会改名为“编程实践”；教师自定义的名称与说明保持不变。实际人数、提交率会随已有用户数据与后续选课、提交变化，上表是全新数据库的初始状态。

## 推荐演示顺序

1. 使用 `teacher` 登录，进入 C++ 程序设计（升级库可能为“编程实践”），切换到“选课学生”，查看姓名、账号、选课时间；桌面每行 3 人，移动端每行 1 人。
2. 打开“两数之和：返回下标”，核对初始应提交 8 人、已提交 6 人、未提交 2 人、提交率 75%；筛选未提交可看到 `student07`、`student08`。
3. 退出后使用 `student01` 登录，在提交记录中查看已有评分反馈；“已选课程”显示 2 门课程。
4. 使用 `student07` 登录，进入已选课程查看尚未提交的作业。实际提交会调用该作业配置的模型与沙箱，并改变未提交人数和提交率；只浏览页面不会改变统计。
5. 使用任一学生账号，在“全部课程”中选择 Python 程序设计，再到“已选课程”核对选课结果。
6. 使用 `teacher02` 登录，在 Python 程序设计中查看新增选课学生，并从课程内发布作业。该账号无法管理李老师的课程。

导入和查看原有反馈不需要调用 DeepSeek。新提交、模型辅助评分和生成测试用例需要对应配置与服务可用；原作业超过截止时间后，需要教师先调整截止时间才能继续提交。

## 更新已有演示数据库

将 `server/config.yaml` 中 `seed.enabled` 设为 `true`，重新构建并启动 API；不需要删除数据库或 MySQL 数据卷：

```bash

docker compose up -d --build server
```

本地开发时，保持 `seed.enabled: true` 并重启 Go API 即可。初始化按账号、课程与选课联合主键补齐缺失记录；保留已有账号密码、课程修改、作业截止时间、代码、成绩与教师复核。补齐后可以关闭 seed。

## 清空并重新初始化演示库

以下示例用于恢复全新的演示状态，会永久清空全部账号、课程、选课、作业、提交、评估任务及人工评分，`TRUNCATE` 不能回滚。仅补充新示例账号或课程时，使用上一节的更新方式即可。

先停止后端，避免评估 Worker 继续写入。Compose 部署在项目根目录执行；本地 `go run` 或 `make server-dev` 则在对应终端停止进程。

```bash
docker compose stop server
```

连接 MySQL 后，先选择并核对数据库。示例库名为 `codeeval`，如修改过 `database.name`，需替换为实际的演示库名。以下 SQL 在同一连接中执行：

```sql
USE codeeval;
SELECT DATABASE();

SET FOREIGN_KEY_CHECKS = 0;

TRUNCATE TABLE evaluation_job_records;
TRUNCATE TABLE expert_rating_records;
TRUNCATE TABLE review_records;
TRUNCATE TABLE submission_records;
TRUNCATE TABLE test_case_records;
TRUNCATE TABLE enrollment_records;
TRUNCATE TABLE assignment_records;
TRUNCATE TABLE course_records;
TRUNCATE TABLE users;

SET FOREIGN_KEY_CHECKS = 1;
```

共 9 张表，包含新增的 `enrollment_records`（选课关系）和 `course_records`（课程）。不要给 SQL 行加 `#` 注释符；若中途报错，处理后确认执行恢复外键检查的语句。

在 `server/config.yaml` 中保持 `seed.enabled: true`，再启动最新后端。Compose 部署执行：

```bash
docker compose up -d --build server
```

本地开发则在项目根目录执行以下命令，与 Compose 方式任选其一：

```bash
make server-dev
```

初始化完成后退出网页旧会话，重新登录。全新状态应为 2 位教师、8 名学生、3 门课程、11 条选课关系、1 项作业、6 份已评分提交，教师复核、专家评分及评估任务均为空。课程名称为“C++ 程序设计”“数据结构与算法”“Python 程序设计”。

通过页面执行全班查重：6 人、15 组配对。张同学与孙同学的改名样例相似度 **100%**，双方第 **3–20 行**匹配，共 **118 个词元**。这组样例用于验证标识符改名识别；检测不自动认定抄袭或扣分。

## 导出与校验

在 `server/` 目录运行以下命令，可只读导出指定作业中六名学生最新的已评分提交：

```bash
go run ./cmd/export-seed -assignment 1 -output /tmp/recorded-seed-new.json
```

导出器不迁移或修改数据库，不覆盖已有输出文件；缺少学生、完整评分、实际模型调用、沙箱结果或耗时则停止导出。用新快照替换内置文件前，应核对账号范围、题目及每份结果。
