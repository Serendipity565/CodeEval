# 提交与评估

[文档首页](README.md) · [项目首页](../README.md)

## 程序与评分规则

支持 Go、Python、Java、C++ 的标准输入/标准输出程序。Go 代码需要 `package main` 和 `func main()`；Java 需要 `Main` 类及 `main` 方法；C++ 需要 `int main()`。请提交完整程序，不要只提交函数。

沙箱测试提供执行证据；有测试用例时，功能类评分项按测试权重计算。教师可以启用两阶段 DeepSeek 评估其余维度。关闭模型评估时，没有评分依据的维度标为“未评分”，不再分配占位分数；存在未评分项的提交不计入平均成绩，待教师完成复核。历史本地占位结果读取时也应用这一规则，原始数据库 JSON 保留。隐藏用例的输入和期望输出不会通过学生作业接口返回。每份作业的提交次数上限由教师设置。

## 评估队列与状态

提交和评估任务在一个数据库事务中写入；Worker 从 MySQL 队列领取任务，状态可为 `queued`、`evaluating`、`needs_review`、`graded` 或 `failed`。

## 提交列表与教师复核

提交列表按“作业 + 学生”仅展示最新一次提交，再对最新提交进行搜索、成绩筛选和排序。同一时间的提交以较大的提交 ID 为准。侧边栏的提交数量采用相同口径；历史提交仍保存在数据库中，不影响提交次数限制或历史详情访问。

提交详情直接展示评分反馈，标题旁提供“查看代码”和“教师复核”（已复核时为“修改复核”）按钮。代码与复核表单分别在弹窗中打开，不占用详情正文；关闭弹窗返回原阅读位置。复核历史在复核弹窗内直接展示。

沙箱测试在正文显示通过数量，点击“查看测试用例”打开详情弹窗；详细代码分析通过“分析证据”按钮查看。公开用例展示输入、期望输出和实际输出，隐藏用例仅显示结果与耗时，不展示输入输出。

在提交详情中，作业所属教师可以按原始评估的量规填写各维度分数和复核理由，发布最终成绩。每次复核追加新记录，保留原始机器评估及所有修订；学生看到最新教师成绩和反馈。并发修改会提示刷新，避免覆盖他人的新复核。

专家独立评分和评分对照功能已移除，对应录入、对照接口不再提供。已有历史专家数据保留，不修改学生成绩。

新自动评估会记录执行和模型评分的总耗时，不含排队等待。

相关接口与数据保存方式见[数据库设计](database.md#review_records)；代码相似片段检测见[代码查重](code-similarity.md)。
